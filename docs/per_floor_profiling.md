# Профилировщик этажей

Встроенный профилировщик DeepRim измеряет **все загруженные карты**, включая
поверхность 0, скрытые подземные/верхние этажи и отдельные колонии. Поддерживаемая
основа проверена по установленной RimWorld 1.6.4871 rev591.

Статус на 13 октября: локальные проверки и два изолированных прогона
RimWorld 1.6.4871 rev591 (все DLC+DBH и только Core) проверили 34 перехвата,
200 тиков четырёх этажей, CSV/TXT и снятие перехватов. Дополнительно выполнен
[обычный DEV-запуск пяти этажей](live_profiling_2026-10-13.md): 22 записи FPS/TPS
с паузой/обычной/третьей скоростью и подложкой включено/выключено, без ошибок.
На этом небольшом стенде устойчивое падение FPS верхних этажей после исправлений
не воспроизведено; проблемное пользовательское сохранение не измерялось.
CSV теперь содержит `observed_target_tps`: нативная третья скорость может менять
цель 360/720 внутри записи, а принудительная пауза даёт 0.

## Как записать

1. Открой колонию. Рядом с кнопкой `LVL` в правом нижнем углу появилась кнопка
   **«Профиль»**. Кнопка доступна и при выключенном навигаторе.
2. Выбери этаж, положение камеры и скорость. Подожди, пока прогрузятся секции.
   Выключи подробное debug-логирование overlay для сопоставимых замеров.
3. Нажми **«Записать 30 секунд»**. Окно не ставит игру на паузу. Его можно закрыть:
   запись продолжится и автоматически остановится по реальному времени.
4. После остановки автоматически сохраняются **CSV и TXT**. Точный путь виден
   в окне и в Player.log после `[DeepRim Vertical][Profiler] Report:`.
   Папка: `<папка сохранений RimWorld>/DeepRimVertical/Profiles/`.
5. Кнопка **«Остановить»** завершает запись раньше. **«Сохранить отчёт»** повторяет
   экспорт последней завершённой записи, например после временной ошибки доступа.

Перехваты дорогих методов устанавливаются только при запуске записи и снимаются
после неё. Снятие затрагивает только owner `gerbe.deeprim.vertical.profiler`,
не функциональные патчи мода или другие профилировщики. Новая запись очищает
счётчики; возврат в меню/очистка игры завершает прежнюю запись. Данные профиля
не сохраняются в колонию и не содержат вторых экземпляров пешек/предметов.

Обновление 13 октября: 34 перехвата, отдельные GUI/расходы окна, нейтральная
подложка, планирование работы/маршрутов, задания, инженерия, бухгалтерия,
потолки, DBH и граф питания. Неудавшиеся тики больше не увеличивают успешный
TPS; `tick_attempts` сохраняет число попыток. [Полный аудит и пробелы](mod_logic_audit_2026-10-13.md).

## Что видно

- Реальные TPS по числу завершённых вызовов игрового тика за время записи.
  На паузе TPS равны нулю. Скорости, включая forced slowdown, фиксируются в отчёте.
- Среднее, верхняя оценка p95 и максимум времени тика; интервал между обновлениями
  кадра и CPU-время `Root_Play.Update` представлены отдельно.
- По каждой карте: **мс симуляции на игровой тик**, мс `MapUpdate` на кадр,
  число вызовов полного сброса site. Метаданные включают site, уровень, размер,
  число объектов и пешек при первом наблюдении.
  Вызов сброса относится к карте-источнику события; пересборки его потребителей
  измеряются отдельно на соответствующих этажах.
- Детализация: системы карты до/после тика, температура, электричество,
  обслуживание поиска путей, поиск работы, синхронизация климата, переходы,
  инвалидация, фактические пересборки состояния клеток/опор/terrain/mask,
  секции подложки, подбор render workers и ghost overlay.
- Наиболее затратные отдельные пешки и агрегаты других объектов по `defName`.
  Для клетки/стопки без карты расходы отображаются отдельно как «Без карты».
- Изменение managed heap и число сборок GC по поколениям; список активных модов,
  версия игры, настройки overlay, пределы покрытия и причина окончания.

Симуляция этажа = `MapPreTick + внешние Thing.DoTick + MapPostTick`.
Содержимое контейнеров/инвентаря включено в время внешнего владельца один раз.
Детализация вложена в эти родительские расходы. **Нельзя складывать все строки**:
например, поиск работы уже включён во время пешки, а время пешки — в этаж.
`MapUpdate` включает обслуживание карты и рисование; его не прибавляют к мс/тик.

## Проверка лагов на ускорении

На одной копии сохранения, с одинаковым положением камеры, запиши:

| Запись | Зачем |
| --- | --- |
| Пауза, проблемный этаж | Изолировать обновления карт, кеши и рисование |
| 1×, тот же этаж | Базовая стоимость симуляции |
| 3×, тот же этаж | Увидеть рост стоимости/падение фактических TPS |
| 3×, поверхность 0 | Проверить зависимость от выбранного для просмотра этажа |
| Пауза/3×, верхний этаж, overlay выключен | Сравнить стоимость подложки; остальные симуляции карт остаются |

Не меняй скорость внутри одной записи: для каждой скорости нужна отдельная.
Для строгого сравнения каждый вариант начинай с той же копии сохранения и
повторяй три раза. В первый раз открытие окна/запуск может прогревать JIT и шейдеры;
не принимай единичный начальный всплеск за постоянную причину торможения.

Чтение результата:

- Большое мс/тик конкретного скрытого этажа указывает на его симуляцию, а не
  на необходимость выбрать его для просмотра. Смотри temperature/power/things.
- Высокое время `JobSearch` или конкретной пешки — основание проверить её
  задание и пути; это ещё не доказательство бесконечного перепланирования.
- Большое время `MapUpdate` на паузе, частые mask/terrain/support rebuilds или
  full invalidations — основание исследовать обновления/рендер/кеши.
- Если тик быстрый, но интервалы кадров большие, проверь CPU frame scopes,
  GPU/vsync, окна и другие моды. Профилировщик не измеряет GPU напрямую.
- Отдельно проверь Player.log на повторяющиеся ошибки: счётчик исключений в
  профиле видит только исключения, вышедшие из измеряемого метода. Ошибки,
  которые игра перехватила внутри метода, могут быть видны только в логе.

## Пределы измерения

Это Stopwatch-профиль главного потока, не полный Unity Profiler. Инструментация
добавляет нагрузку во время записи; сравнивай одинаковые режимы записи. Native
Mesh/Material/VRAM, GPU и выполнение path jobs на рабочих потоках не измеряются.
`PathService` учитывает время главного потока на планирование, завершение и ожидание
этих jobs. Изменение heap не равно объёму всех аллокаций.

p95 — верхняя оценка фиксированной гистограммы за всю запись. Самые длинные
вызовы сохраняются в max. Число строк ограничено 4096, включая не более 1024
строк детализации объектов; пропущенные образцы отмечены в CSV/TXT. Такие
строки не гарантируют полный рейтинг каждой пешки очень большой колонии.
Не использовать dev fast ecology для обычного сравнения: оно меняет шаг тика
и вызывает часть растительных тиков напрямую, вне обычного `Thing.DoTick`.

## Локальные и игровые проверки

`tools/validation/test-profiler.ps1` проверяет распределение времени/выбросы,
непересекающиеся итоги этажей, TPS, CSV с русской локалью и кавычками/переносами,
23 сигнатуры методов/инъекции полей установленного движка, вложенные владельцы,
изоляцию эпох записи и переводы. CLR-проба проверяет сохранение исходного
исключения и снятие только своего owner.

Фактическая установка всех перехватов и полный capture требуют запуска в
Unity/Mono игры. Компьютерные .NET Framework/Core имеют отличия от этого runtime;
контрактные/CLR проверки не объявляются игровым тестом.

В игре проверить: запись на паузе завершается; закрытие окна не останавливает
запись; 1×/3× дают разные TPS; все этажи присутствуют; CSV/TXT создаются;
повторная запись не удваивает число вызовов; остановка/выход в меню снимают
перехваты; сохранение/загрузка не включают профилировщик автоматически.
