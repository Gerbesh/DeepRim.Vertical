# Приёмка единой вертикальной колонии

Сценарии к [аудиту систем](colony_systems_audit.md), 11 октября 2026. Это критерии будущей реализации, **не отчёт о пройденных проверках**. Текущая сборка не реализует большинство межэтажных систем.

Для каждого сценария сохранять build/version, моды/DLC, site/map/level, начальное состояние и результат. Для экономических проверок принудительно обновлять локальные counters на одной и той же границе тика: их обычные кеши могут скрыть ошибку или дать временное расхождение. Для боевых проверок фиксировать seed/режим точности и проверять intended target отдельно от реального попадания.

## Экономика и рассказчик

| ID | Действие | Ожидаемое поведение |
|---|---|---|
| E1 | Перенести одинаковую пачку стали 0→−1→+1 | Сводная стоимость предметов неизменна; локальные вклады меняются; readout соответствует выбранной семантике хранения |
| E2 | Перенести пешку с одеждой, оружием, инвентарём и carried stack | Каждый объект учтён один раз, включая груз в пути; население колонии не меняется |
| E3 | Положить вещи в shelves, контейнеры и vanilla pocket map при site | Нет пропуска и двойного включения holders/pocket subtree |
| E4 | Открыть/закрыть fog, добавить гостя, quest lodger, пленника/раба, животное/меха | Применяются выбранные ванильные правила богатства и threat population, а не сумма всех Thing на картах |
| E5 | Добавить пустые этажи при фиксированном внешнем богатстве и населении | Колониальные исходные параметры угроз и число независимых колониальных циклов не меняются; допустимые локальные события сохраняются |
| E6 | Сравнить историю богатства с угрозами; проверить terrain/foundation | Полный вес зданий в истории; 0.5 в угрозах; FloorsOnly не прибавляется второй раз |

| E8 | Две отдельные колонии + караван + вертикальный site | Каждая колония учитывается отдельно; события/имущество другого site не подмешиваются |
| E9 | Поставить событие в очередь до save/load или удаления этажа | Цель корректно разрешается; событие не дублируется, явно локальное событие не исчезает молча |

## Логистика, работа и потребности

Использовать подробные [R/W/H/B сценарии](cross_level_colony_test_plan.md). Дополнительно обязательны сквозные проверки:

| ID | Действие | Ожидаемое поведение |
|---|---|---|
| L1 | Добыча −2, склад −1, стройка +1, станок 0, результат +2 | Все этапы выполняются автоматически с реальными предметами и рабочими приоритетами |
| L2 | Две пешки, одна пачка, один почти полный shelf | Claims количества и места предотвращают двойное назначение, потери, вечное ожидание |
| L3 | Равные приоритеты складов, затем сменить filters/priority в пути | Нет маятника переносок; назначения пересчитываются, груз не пропадает |
| L4 | Работа высокого приоритета внизу и постоянная низкого наверху | Удалённая приоритетная работа не голодает; emergency needs/draft корректно прерывают задачу |
| L5 | Save/load до лестницы, во время перехода, с грузом, при передаче ингредиента | Сохраняется цель операции; нет двух владельцев вещи, повторного расхода или вечных claims |
| L6 | Уничтожить лестницу/станок/ресурс/склад на каждом этапе | Альтернативный маршрут либо понятная отмена; локальные и общие резервы освобождены |
| L7 | Кровать внизу, еда наверху, пациент −2, врач 0 | Сон, кормление, tending/rescue используют доступные цели; недостижимые кровати/еда не скрывают предупреждения |
| L8 | Allowed/home areas, forbidden door, опасная лестница, животное с fence | Путь уважает ограничения конкретного исполнителя, в том числе при поиске запасной посадки |
| L9 | Сформировать караван/торговлю с вещами и пешками разных этажей | Реальный сбор к выходу/торговцу, корректное списание; груз не продаётся дважды и не исчезает из незавершённой задачи |
| L10 | Mech charging/control, prisoner escort, animal hauling | Проверены отдельные роли/ограничения; неподдерживаемый случай обозначен явно |

Для S10/S11 использовать [гайд профилировщика](per_floor_profiling.md). Он измеряет основной поток CPU; GPU, background workers и native allocations требуют дополнительных средств. Нельзя считать падение TPS доказательством конкретной причины без разделения затрат.

Каждый DLC/сторонний мод проверять после базовых E/L/C/S сценариев и повторять затронутые сценарии: rituals/roles, royal room requirements, mechanitor range/charging, anomaly entities/pocket maps, Odyssey gravship/world-layer lifecycle, нестандартные storage/power/pipe/weapon systems. Факт загрузки DLL не является проверкой совместимости.
