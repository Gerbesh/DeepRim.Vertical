# Приёмка работы колонии между этажами

Обновление 12 октября: первая реализация покрывает часть этих требований. [Текущий план проверки](vertical_routing_test_plan.md) перечисляет поддержанные адаптеры и ограничения; этот документ сохраняет полную приёмку будущей колонии.

Статус: сценарии для будущей реализации. На 2026-10-11 автороутинг, общий
планировщик, claims и межэтажная логистика отсутствуют; ожидаемые результаты
ниже не являются результатами уже проведённых тестов.

Проект: [cross_level_colony_design.md](cross_level_colony_design.md).
Проверяем сначала чистую RimWorld 1.6.4871 с Harmony и DeepRim Vertical;
затем отдельно DLC и моды с заявленными адаптерами.

## Стенд

- Копия тестового сохранения, 3 этажа: 0, -1, -2. Один site; отдельная колония
  на другой клетке мира служит контролем границы поиска.
- Связанная лестница A: 0↔-1; лестница B: -1↔-2 с другими XY.
  Проход между A и B. Дополнительная лестница C для альтернативного пути.
- На 0 склад стали/дерева/еды; на -2 чертёж, станок, принимающий склад и кровати.
- Два колониста с явными числовыми приоритетами: строительство 1, добыча 2,
  переноска 3. Доставщикам разрешены нужные виды работы.
- Доступные клетки этажей разведаны обычным способом. Переключение просмотра
  не переносит пешек и не выдаёт им дополнительных приказов.
- Для тестов грузов записать исходное количество и владельца каждой стопки.
  Включить dev-инспектор intent/route/claims и журнал ошибок.

## A. Маршруты и продолжения

| ID | Действие | Ожидаемое поведение |
| --- | --- | --- |
| R1 | Приказ цели на -2 колонисту с 0 | Сам проходит A, коридор -1, B; начинает действие по точной цели -2; камера не переключается |
| R2 | Две лестницы на -1 разделить стеной | -2 признаётся недоступным; отсутствие бесконечной ходьбы и чтения той же XY на неверной карте |
| R3 | Сравнить короткий путь с дорогим обходом | Выбор меньшего времени маршрута, а не просто меньшего количества этажей/ближайшей первой лестницы |
| R4 | Разрушить A или закрыть выход во время движения | Перепланирование через C либо понятный отказ/ожидание на текущем этаже; пешка остаётся в мире |
| R5 | Перекрыть клетку выхода стеной, затем освободить | Нет случайного Spawn по другую сторону стены; после открытия маршрут снова доступен |
| R6 | Запретить область вокруг B, открыть пустоту верхнего этажа | Оба препятствия учитываются; пешка не проваливается в UpperVoid и не нарушает область |
| R7 | Отправить несколько пешек через одну лестницу | Расходятся/ждут без вечного эксклюзивного резерва и без зависания в одной клетке |
| R8 | Новый приказ на подходе; затем серия Shift-приказов разных этажей | Первый маршрут отменяется; очередь исполняется по одному разу, на правильных картах |
| R9 | Призыв, incapacitation, смерть, mental break на разных этапах | Цепочка корректно прерывается; обязательства освобождаются, пешка/груз не исчезают |
| R10 | Сохранить/загрузить на подходе, у входа, после Spawn и перед местной работой | Та же цель и груз, корректное продолжение, без двойного перехода/действия |

## B. Автоматическая работа и конкуренция

| ID | Действие | Ожидаемое поведение |
| --- | --- | --- |
| W1 | Добыча на -2; подходящий рабочий на 0 без ручного приказа | Сам находит назначение, переходит и добывает; прогресс назначенной цели сохраняется |
| W2 | Уборка/ремонт на одном этаже, низкоприоритетная местная переноска на другом | Учитывает work settings и priorityInType; важная удалённая работа не теряется за местной переноской |
| W3 | Два рабочих и одна удалённая цель | Только допустимое число исполнителей получает эту цель; второй выбирает другую работу |
| W4 | Одновременно местный job и удалённый intent претендуют на одну стопку | Сумма резервов/обещаний не превышает реальное количество; местные задания видят claims |
| W5 | Смена работы/доступа к этажам и `preferSameLevelWork` | Существующие цепочки безопасно завершаются/отменяются; новые obey настройки без инверсии приоритетов |
| W6 | Удалить цель, сменить фракцию, сдвинуть вещь на другой этаж | Перепроверка или отмена с освобождением ресурсов; никакой работы в старой XY по другому объекту |
| W7 | Цель у отдельного site с совпадающими XY или на том же world tile | Не попадает в колонистский поиск текущего site |
| W8 | Местное задание стороннего мода без адаптера | Продолжает работать на своём этаже; не объявляется межэтажно совместимым |

## C. Склады, стройка, предметы

| ID | Действие | Ожидаемое поведение |
| --- | --- | --- |
| H1 | Стройка на -2, все материалы на 0 | Колонисты сами подбирают, проходят маршрут, доставляют и заканчивают Frame |
| H2 | Один стек 100 стали; две стройки требуют 80+80 | Нельзя обещать 160; одна доставка ждёт/ищет другой источник, фактическая сталь сохраняется |
| H3 | Высокоприоритетная полка -2 и обычный склад 0 | Переноска соблюдает фильтр/приоритет; равные приоритеты не запускают качание стопки между этажами |
| H4 | Заполнить склад/изменить фильтр после подбора | Выбран другой подходящий получатель или безопасная местная выгрузка; остаток не теряется |
| H5 | Разделить/слить исходную стопку, частичная выгрузка | Claims пересвязываются/пересчитываются, нет дублирования и отрицательных количеств |
| H6 | Отменить Blueprint; Blueprint превращается в Frame при доставке | Demand относится к актуальному получателю, отменённое больше не снабжается |
| H7 | Отключить hauling/превысить лимит; запретить item transfer на портале | Новая запрещённая доставка не выдаётся; поднятый груз завершается безопасно |
| H8 | Сохранить с грузом в руках и с частью в Frame | После загрузки правильные владельцы, суммы и оставшаяся потребность; нет повторного подбора/выгрузки |
| H9 | Ручной приказ отменяет доставку, доставщик умирает на лестнице | Груз доступен в законном владельце/на карте, свободные claims не висят бесконечно |

Проверка сохранности: исходное количество + реально добыто/произведено минус
реально израсходовано/уничтожено = сумма по всем настоящим владельцам всех этажей.
UI-счётчик свободных складских ресурсов не заменяет эту проверку.

## D. Станки и повседневная жизнь

| ID | Действие | Ожидаемое поведение |
| --- | --- | --- |
| B1 | Заказ на -2, подходящие ингредиенты на 0, исполнитель на -1 | Доставка на этаж станка, обычное исполнение, готовая вещь по правилам назначения заказа |
| B2 | Фильтр материала, no-mix рецепт, skill/worker restriction | Именно разрешённый набор и исполнитель; неподходящая общая сумма не запускает заказ |
| B3 | Пауза/удаление заказа во время снабжения; незавершённое изделие | Нет лишнего повторного производства; сохраняются BoundUft/creator; staging claims освобождаются |
| B4 | «До количества», изделия на разных этажах; затем выбран конкретный склад | Подсчёт по выбранной области; отсутствие двойного учёта и превышения из-за разных карт |
| B5 | Только еда и назначенная кровать на 0, работник на -2 | Сам проходит к подходящей еде/кровати, затем возвращается к разрешённой работе |
| B6 | Еда запрещена диетой/областью, кровать недоступна | Выбор подходящей альтернативы/обычный fallback; голод не вызывает бесконечный поход к недопустимой цели |
| B7 | Пациент -2, лекарство/больничная кровать 0 | Лечение/спасение используют маршрут и настоящие ресурсы; перенос пациента не роняет его на каждом этаже |
| B8 | Refuel/hopper на -2, несколько доставщиков | Обещанная ёмкость учитывается, топлива/еды не несут сверх необходимости |

## E. Общая колония и границы поддержки

- Ресурсная сводка меняет этажную детализацию, сохраняя общую корректную сумму;
  счётчик доступности не предлагает чужие зарезервированные/переносимые вещи.
- Alerts о кроватях, рабочих и пище согласованы с назначениями/доступностью site.
- Wealth учитывает колонию один раз; внутренние MapParent не создают повторные
  инциденты. Другие колонии сохраняют независимую экономику.
- Торговля/караван собирают заявленные предметы/пешек на поверхности реальными
  маршрутами, не позволяют одновременно обещать их стройке.
- Животные, механизированные рабочие, дети, пленные и гости проверяются отдельными
  сценариями их адаптеров/разрешений. Поддержку DLC подтверждать с активным DLC.
- Power/heat/pipes и боевой LOS имеют отдельные проверки и статус. Флаг в записи
  портала или успешное перемещение пешки не доказывает работоспособность канала.

## F. Производительность и сбои

Сравнить базовую сборку и реализацию в одинаковом сохранении/скорости: 1 и 20
пешек, 3 и 20 этажей, множество вещей/назначений, нет доступных лестниц, разрушение
лестницы и загрузка. Записать TPS и время планировщика, число проверок пути/тик,
время выдачи задачи, объём кешей и частоту полных сканирований. Целевые бюджеты
назначаются по этим измерениям, а не объявляются заранее достигнутыми.

Проверить восстановление при искусственном отказе Spawn, выгрузки, локального
резерва и разрешения load reference. Ни один отказ не должен оставлять бесхозную
пешку/вещь, дублировать материю или подавлять все последующие задания.

Автоматические проверки нужны для логики графа и инвариантов:

- граф с недостижимыми местными участками, разными XY, направленными/запрещёнными
  рёбрами, конкурирующими маршрутами и версионной инвалидацией;
- транзакции claims, rollback, подсчёт частей стопки и пересечение local reserve;
- сериализация/восстановление intent в каждом устойчивом состоянии и повторные
  callbacks доставки без двойной выдачи;
- границы выбора работ и складов по priority/filter/site.

Эти тесты дополняют реальные сценарии RimWorld, не заменяя работу живых драйверов,
патчей Harmony, карт, carryTracker и сохранений.
